# World Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a 3D voxel world map on which the player walks Blorp along a path and plays any opened level.

**Architecture:** The map's rules (the island grid, the route, what is open, walking) live in one new source piece with no three.js in it, so the Node checks can drive them. A second new piece draws the island into its own group in the existing scene and animates Blorp and the camera on it. The flow code gains a `map` state that sits between levels, and the save gains the furthest level opened.

**Tech Stack:** Plain JavaScript in one page, three.js r128 from the CDN, Web Audio. Node.js for the checks. No dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-world-map-design.md`

## Global Constraints

- No image or sound files. Models are boxes through `voxGeo`, colours come from `THEMES`, sound from the synthesiser.
- One renderer, one scene, one camera. three.js stays at r128.
- The world, layout, landmarks and tune are original to this game. Nothing is copied from Super Mario World.
- Along the route the ground changes by at most one height step between neighbouring cells.
- Rules code must run under the stubs in `tools/game.js`: no arithmetic on values read from three.js objects.
- Every use of local storage may fail quietly.
- A save written before this change must still load.
- `node tools/check-levels.js` and `node tools/check-save.js` pass at the end.
- The source style of the repo is kept: dense single-purpose files, section banners, comments that say why.

## Review Focus

1. **Keys held across a screen change.** Holding Right or Space when a level ends, then landing on the map: Blorp must not walk off or re-enter a level without a fresh press. Pinned in Task 2 (enter needs an edge) and Task 4 (touch A needs an edge).
2. **Phone turned or window resized on the map, then a level started.** The level camera's lift is measured from the touch keys, whose layout differs on the map. `layout()` must run on every switch between map and level. Pinned in Task 4 by a browser check.
3. **A press during the path-appearing animation or mid-walk.** Must be ignored, not queued, and must not start a level. Pinned in Task 1 (`mapGo` returns `'busy'`) and Task 2 (`mapEnter` refuses).
4. **A save that says more is open than exists, or Blorp standing past what is open.** Read as the old format: open up to `level`. Pinned in Task 2.
5. **The tab hidden while the path is appearing.** Frame time is already clamped to 0.1 s; the animation must finish from any step size. Pinned in Task 1 by ticking with a 0.1 s step.

### Task 1: The island, the route and the rules of walking

**Files:**
- Create: `src/f_map.js`, `tools/check-map.js`
- Rename: `src/f_flow.js` to `src/h_flow.js`
- Modify: `build.sh` (PARTS), `tools/game.js` (PARTS), `src/e_play.js` (the `G` object)

**Interfaces:**
- Consumes: `LEVELS`, `LABELS`, `WORLDS` from `src/b_levels.js`; `G` from `src/e_play.js`; `rng`, `clamp` from `src/a_art.js`.
- Produces:
  - `G.open`: integer 0 to `LEVELS.length`. Level `i` is open when `i<=G.open`, cleared when `i<G.open`.
  - `MAP_W=46`, `MAP_D=30` (cells), `MAP_STEP=0.5` (world units per height step).
  - `MK_SEA=0, MK_LAND=1, MK_LAVA=2, MK_GOO=3, MK_POND=4`.
  - `ISLE={h,base,world,kind,deck,route}`: typed arrays of `MAP_W*MAP_D`, index `z*MAP_W+x`. `h` land height in steps (0 for none); `base` the bottom of a floating column in steps (0 for a column that reaches the seabed); `world` 0 to 5 or -1; `kind` one of the `MK_` values; `deck` the height of a bridge or stair deck (0 for none); `route` the route cell's order number or -1.
  - `MAPNODES`: array of `{x,z,h}`, one per level, in level order.
  - `MAPSEGS`: array of `MAPNODES.length-1` arrays of `{x,z,h}`, each running from marker `i` to marker `i+1` and including both.
  - `mapStandH(x,z)`: steps at which Blorp stands on a cell (deck if any, else land).
  - `mapDirAt(i)`: `{fwd,back}`, each `'N'|'E'|'S'|'W'|null`. North is `-z`.
  - `MAPST={at,walk,reveal,x,y,z,face,moved}`: `at` marker number; `walk` null or `{seg,dir,k,t}`; `reveal` null or `{seg,k,t}`; `x,y,z` Blorp's place in world units; `face` a compass letter.
  - `mapPlace(i)`: stand Blorp on marker `i`, cancel any walk.
  - `mapGo(dir)`: returns `'go'`, `'locked'`, `'none'` or `'busy'`.
  - `mapTick(dt,held,fast)`: advance a walk or a reveal; `held` is a compass letter or null. Calls `mapArrived()` on reaching a marker and `mapStepped()` on each tile.
  - `mapReveal(seg)`: start the path-appearing animation for a stretch.
  - `mapSegShown(seg)`: how many of that stretch's tiles are showing.
  - `mapMarkState(i)`: 0 locked, 1 open, 2 cleared. The marker at the end of a stretch that is still appearing reads as locked.
  - Timings: `MAP_HOP=0.14` s per tile, `MAP_HOP_FAST=0.085`, `MAP_TILE=0.09` s per appearing tile.

Run `./build.sh` (expect `script syntax ok`) and `node tools/check-save.js` (expect `all 10 checks pass`).

- [ ] **Step 2: Write `tools/check-map.js` with the failing checks.** Same shape as `tools/check-save.js`: a `checks` list of `[name,run]`, `ok`/`FAIL` lines, exit code 1 on any failure, plus `--map` to print the island as text. Probe: `{G,MAPNODES,MAPSEGS,ISLE,MAP_W,MAP_D,MK_SEA,MK_LAND,MAPST,mapPlace,mapGo,mapTick,mapReveal,mapSegShown,mapMarkState,mapDirAt,mapStandH,LEVELS}`. Checks:
  - `there is one marker for every level`: `MAPNODES.length===LEVELS.length`, `MAPSEGS.length===LEVELS.length-1`.
  - `every stretch of path moves one cell at a time, north, south, east or west`: for neighbours `a,b` in each stretch, `|a.x-b.x|+|a.z-b.z|===1`; each stretch starts on its marker and ends on the next.
  - `the path stays on the island, a bridge or a stair`: every cell inside the grid and `mapStandH(x,z)>0`.
  - `markers stand on land in their own world`: `ISLE.kind` is `MK_LAND`, `ISLE.deck` is 0, and `ISLE.world` equals the level's world (level `i` is world `Math.floor(i/5)` taken from `LEVELS[i]().world`).
  - `the path never changes height by more than one step`: neighbours differ by at most 1 in `mapStandH`.
  - `the path never crosses itself`: no cell appears twice across all stretches apart from shared markers.
  - `no two stretches leave a marker the same way`: `mapDirAt(i).fwd!==mapDirAt(i).back` for every marker; marker 0 has `back===null`, the last has `fwd===null`.
  - `with nothing cleared Blorp cannot leave the first marker`: `G.open=0; mapPlace(0); mapGo(mapDirAt(0).fwd)==='locked'`, and the other three directions give `'none'`.
  - `with N levels open Blorp can walk to marker N and no further`: `G.open=3`; walk forward by `mapGo` then `mapTick(1/60,null,false)` until `MAPST.walk===null`; expect `at` 1, 2, 3 in turn, then `'locked'`.
  - `Blorp can walk back to the start`: from marker 3 go `back` three times; `at===0`; `mapGo(back)` is `'none'`.
  - `a press while walking is ignored`: after a `'go'`, `mapGo` of any direction is `'busy'`.
  - `holding a direction carries on through a marker`: find a marker whose `fwd` equals the `fwd` of the one before; tick with `held` set to it from the earlier marker and expect to pass straight through.
  - `a new stretch of path appears tile by tile and then opens its marker`: `G.open=1; mapPlace(0); mapReveal(0)`; `mapSegShown(0)===0`, `mapMarkState(1)===0`, `mapGo` is `'busy'`; tick with `dt=0.1` until `MAPST.reveal===null` (bounded loop); then `mapSegShown(0)` is the stretch's full tile count, `mapMarkState(1)===1`.
  - `markers read as locked, open and cleared`: `G.open=2` gives states `2,2,1,0` for markers 0 to 3; `G.open=LEVELS.length` gives 2 for the last.

- [ ] **Step 3: Run `node tools/check-map.js`.** Expected: every check FAILs (the names are not defined).

- [ ] **Step 4: Write `src/f_map.js`.**
  - A `MapBuilder` in the spirit of `LevelBuilder`: `blob(cx,cz,rx,rz,world,h)` (an ellipse of land with a slightly ragged edge from a fixed-seed hash), `raise(cx,cz,r,dh)` (a stepped dome added to land already there), `flat(cx,cz,rx,rz,h)`, `pool(cx,cz,rx,rz,kind)`, `lift(cx,cz,rx,rz,base)` (mark land as floating), `route(x,z,moves)` (the start cell and one string of compass letters per stretch).
  - The island follows the spec's table and sketch: meadow south-west, sunken grotto south-middle, castle rock in a lava moat south-east, the mountain north-east with 4-5 on the summit, dunes north-middle, the floating citadel north-west reached by at least ten stair cells.
  - Laying the route: take the land height under each route cell; cells with no land get a deck whose height is interpolated between the land at either end of the gap; then clamp forwards and backwards until neighbours differ by at most one step; write the result back into `h` (land) or `deck` (gaps). Algorithm fixed because the checks depend on it.
  - The walking rules as listed in Interfaces. `mapArrived()` and `mapStepped()` are declared in `src/h_flow.js` (Task 2); in this task declare them there as empty functions.

- [ ] **Step 5: Run `node tools/check-map.js` and `node tools/check-map.js --map`.** Expected: all checks pass; the printout shows six regions and the route.

### Task 3: Drawing the map

**Files:**

**Interfaces:**

- [ ] **Step 1: Write the view.**
  - Terrain: one merged mesh, two boxes per land cell (a body in the world's dirt colour and a cap in its top colour, each varied a little per cell from a fixed hash), floating cells cut off at `base` with a narrower underside, pools as glowing flat boxes, decks as planks (bridges) or glowing slabs (stairs).
  - Sea: one large plane with a scrolling 16-pixel texture, a lighter shelf box on sea cells that touch land, and a soft dark patch under the floating island.
  - Props: per-cell from a fixed hash by world, at half the level scale, never on a route cell or beside a marker; hand-placed landmarks (Blorp's hut by 1-1, pyramids, big mushrooms).
  - Markers: one group per marker with a locked, an open and a cleared mesh; castle and tower for the two boss levels. The open one pulses.
  - Path: one `InstancedMesh` of pale tiles; `mapViewSync()` sets each tile's matrix from `mapSegShown`.
  - Blorp: `proot` at `MAPST.x,y,z`, turned to `MAPST.face` while walking and to the camera when standing, a hop arc and foot swing while walking, the title's wave when idle, `shadow` on the cell under him.
  - Camera: looks at Blorp from the south at 50 degrees, eased, clamped to the island's edges; distance from the existing `V` so about 15 cells of depth show.
  - Look: `stage.style.background` to sea blue, `scene.fog=null`, daylight on `hemi` and `sun`. `loadLevel` already restores a level's look through `applyTheme`.
  - Banner: `#map-banner` in the stage, under the HUD: label, world name, a `Cleared` tag, and the hint (`Space to play` / `A to play`). `mapBanner(note)` fills it; a note such as `Clear this level to open the path` replaces the hint for 1.6 s.
